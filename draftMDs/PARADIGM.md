# PARADIGM.md: nothing is hidden (draft)

Provisional; breaking changes are expected. Intended for the root once it
settles.

## 1. The principle

**Nothing is hidden**, or as little as possible. Everything about how the
work is done lies open to view in the repo itself, so a reader never has to
excavate. The rest follows from that.

## 2. Facets

1. **Write once.** It is the universal principle: everything is add-only
   except the constitutive rules, the docs, which are articulated by
   updating them. A correction is a new worm. See also
   [`../WORMS.md`](../WORMS.md) for the wormstream.
2. **One branch.** Everything goes straight to `main`, and history is never
   rewritten. See also [`../CLAUDE.md`](../CLAUDE.md), section 1.
3. **Self-describing paths.** A worm's path gives its time and author, so
   the tree is the record.
4. **Secrets kept out at the door**, since nothing can be hidden once it is
   in. Refer to [`SECRETS.md`](SECRETS.md) for what that means here.

## 3. Distinctions

1. **Truth and authority.** The wormstream is the source of truth; the
   tiers give authority. Refer to [`TIERS.md`](TIERS.md) for which text
   wins.
2. **New and old.** Within a tier, the new supersedes the old. Across
   authors, order comes from reference.
3. **Use and mention.** Depending on a text is a use; citing it is a
   mention. Refer to [`BUNDLES.md`](BUNDLES.md) for its first application.
4. **True and fair.** Where a record involves a choice, such as which time a
   name gives, several choices can pass. What matters is that a case can be
   made for the one chosen.
5. **Duty and rank.** Drones maintain and bees create; neither outranks the
   other. Refer to [`ROLES.md`](ROLES.md) for who does what.

## 4. Turned away from

Feature branches, review by pull request, squash merges, rebasing what's
been pushed, and the ideal of a curated history: all ways of telling a
tidier story than what happened. Here the record stays as it happened, and
curation is done only by adding. Refer to [`COMMITS.md`](COMMITS.md) for
how the commits themselves tell it. See also [`../STYLE.md`](../STYLE.md)
for keeping the docs tidy.
